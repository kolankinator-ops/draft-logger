That message comes from Twitch's own player when it cannot load the channel's classification data, which usually means something is blocking its background requests. Worth trying, roughly in order:

  • Allow third-party cookies for twitch.tv; the player keeps its session there.
  • Hit ↻ on a tile to reload just that player.
  • Check the channel is actually live — an offline channel renders black.
  • Open ↗ to confirm the stream plays on Twitch itself.

🧠 Is your judgement reaching the model?

Your draft read, skill read and execution read do not go into the prediction directly — each is converted into a historical win rate for games you rated the same way. If that lookup has few games behind it, a strong read contributes almost nothing.

🌡 Recent form

Whether a bad run is the model breaking or ordinary variance. Compares the last 20 predictions against everything before them, with the range you would expect from chance alone.

💰 Edge vs the market

Accuracy is not the bottom line — beating the price is. A 55% hit rate at 1.90 makes money; 60% at 1.50 loses it. This compares how often your bets won against what the odds implied they should.

📋 Live model track record

The real out-of-sample record of the model you actually bet with. Every game you logged stored the prediction the 13-factor model made at the time, before the result was known — so this needs no simulation and cannot leak. This is the number that matters; the backtest below only covers the 5-factor subset.

🧑 You vs the model

Your blinded reads from the review page, scored against the model on exactly the same games. Games you marked as already known are excluded.

🔥 Bet streaks by champion

Champions where your last several bets all lost — either backing them or against them. Shown alongside how many runs chance alone should produce, so you can tell a signal from ordinary variance.

⚖ Swing champions

Tests whether a champion amplifies the gap between teams — winning more than expected when their side is already favoured, and less when it isn't. That is the measurable version of "only good in the better player's hands". Uses actual results rather than model predictions, so it runs on your whole bulk pool.

⚔ Champion reliability

For every champion in your logged games, how well the model did when it was on the board — either side. The question is not whether a champion wins, but whether the model can read games containing it. High overshoot means the model is more overconfident than usual when this champion appears.

👁 Watchlist

Pre-register a suspicion. Only games logged after you add a champion count toward its result, so the hypothesis is fixed before the data exists — which is what makes it a real test rather than a pattern you found by looking.

📉 Where it fails

Splits the same stored predictions by league, and by how much history the model actually had for the teams involved. If the damage is concentrated where training data is thin, the fix is more data — not a different model.

🔬 Backtest · 5-factor subset only

Walk-forward predicts each game using only games played before it — the same information you actually have live. Leave-one-out uses every other game, including later ones, so it sees the future and will look better than reality. The gap between them is how much your confidence is borrowed from hindsight.

🧪 Factor diagnostic

Scores each factor on its own, walk-forward. Direction is how often a factor pointed at the eventual winner — below 50% means it is pointing the wrong way. Drop it re-runs the whole backtest with that factor switched off: a positive number there means the model gets better without it.

☁ Device sync

Keeps your desktop, laptop and phone on the same data. Every change merges per game, so edits on two devices no longer overwrite each other and deleted games stay deleted.

One-time setup (~10 min, free):
1. Sign in at dash.cloudflare.com (free plan is fine).
2. Open Workers & Pages in the sidebar. Find KV and create a namespace called draft-logger.
3. Back in Workers & Pages → Create → Start with Hello World. Deploy, then Edit code, replace everything with sync-worker.js, Deploy again.
4. On the Worker: Settings → Bindings → Add → KV namespace. Variable name must be exactly SYNC_KV; select draft-logger.
5. Settings → Variables and Secrets → Add, type Secret, name exactly SYNC_CODE, value = any long random string.
6. Copy the Worker's *.workers.dev URL. Paste it and the same secret below, on all three devices.
Syncs automatically a couple of seconds after any change, when you switch back to the tab, and every 45 seconds while it is open.
📈 Live game states

Records gold, kills, towers, dragons and barons every 45 seconds during live games, then labels each timeline with the result. This is the training data a live win-probability bar would need — the kind of thing a chess engine shows on the side. It reuses the polling already happening, so it adds no network traffic.

Collecting every 45s while the app is open, on any screen, across all leagues — the league filter is not applied here because game state predicts outcomes regardless of league. Needs a few thousand labelled games to fit a model, and cannot be backfilled: the feed only serves live and recent matches.

🧹 Duplicate games

The same match can end up stored twice — imported from two sources, or re-imported after ids changed. Duplicates count twice in training, which quietly inflates whatever they contain.
